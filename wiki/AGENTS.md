# AGENTS.md — 知识库维护规范

> 本文件是本知识库的 **schema**。任何 LLM/Agent 在读写 `wiki/` 之前必须先读它。
> 它规定目录含义、页面格式、链接方式与三个工作流（Ingest / Query / Lint）。
> 人与 Agent 共同演进这份文件：发现规则不好用就改它，别绕过它。
>
> **定位：探索型知识库 —— 广度优先、允许假设、链接从简。**
> 但「探索」只针对**选题与提问方式**（读得杂、敢提假设、短链快速铺开），不针对**事实**。
> 准入、存疑、时效三类硬约束见 §6，任何时候不得为了凑页面、凑结构而放宽。
> 一句话：**探索的范围可以宽，落进页面的每一句必须有据。**

---

## 0. 一句话

`raw/` 是不可变的原始来源，`pages/` 下六类目录（`sources|entities|concepts|topics|comparisons|answers`）是 Agent 维护的 wiki 正文，`index.md` 与 `log.md` 是导航与时间线。

知识在 **写入时** 被编译成结构化页面，而不是每次提问时重新检索拼接。

---

## 1. 三层架构

| 层 | 位置 | 谁写 | 规则 |
|---|---|---|---|
| 原始来源 | `raw/` | 人（剪藏、下载、投递） | **只读**。Agent 可以读、可以移动文件做归档，但**永不修改内容** |
| Wiki 正文 | `pages/` 下六个类型目录 + `overview.md` | 仅 Agent | Agent 拥有这一层，人只读 |
| Schema | `AGENTS.md`（本文件） | 人 + Agent 共改 | 改动需说明理由 |

树形速查：

```
wiki/
├── AGENTS.md          本文件，schema
├── index.md           内容目录：所有页面的链接 + 一句话摘要（每次 ingest 必更新）
├── log.md             时序日志：append-only，记录 ingest / query / lint
├── overview.md        全局综述：演化中的论点与知识地图
├── raw/               原始来源层（只读）
│   ├── inbox/           新来源先投这里，待处理
│   ├── articles/        网文、博客、剪藏
│   ├── papers/          论文、报告、白皮书
│   ├── books/           书籍与章节
│   ├── notes/           自己的笔记、会议、想法
│   ├── transcripts/     播客、访谈、讲座转录
│   └── assets/          图片、PDF 附件（Obsidian 附件目录指向此处）
├── pages/             知识层（Agent 独有，单层收口，不与 raw/ meta/ 平铺混放）
│   ├── sources/         每个来源一页摘要页
│   ├── entities/        实体：人物、组织、产品、工具、作品
│   ├── concepts/        概念：术语、理论、方法、模型
│   ├── topics/          主题枢纽页：一个领域的总览与入口
│   ├── comparisons/     对比页：A vs B、方案选型、时间线比较
│   └── answers/         查询产物回填：分析、连接、结论
├── _templates/        页面模板，复制后填写
└── meta/              元层：方法论原文 + 体检快照
    ├── llm-wiki.md      LLM Wiki 方法论原文。只读参考，不产生页面、不进 index.md
    └── lint.md          最近一次体检报告。覆盖写，只留最新一版，历史结论进 log.md
```

**为什么知识层单独收进 `pages/`**：`raw/`、`meta/`、`_templates/` 是基础设施，知识层是内容。物理分开后，`raw/` 下新增一个 `reports/` 也不会和页面类型撞名，扫描与检索的范围也清晰——`pages/` 之下全是页面，`pages/` 之外都不是。

`meta/` 不参与三层架构，也不是页面类型：它存放「本库为什么这么设计」的原始依据，以及体检快照。改 schema 前先回读这里的文档。正文引用写作 `[[meta/llm-wiki|LLM Wiki 方法论]]`。

`meta/` 下两类文件的读写权限不同：`llm-wiki.md` 只读，人也不常改；`lint.md` 是 meta 层唯一由 Agent 写的文件，每次体检**覆盖**，不进 `index.md`。

## 2. 页面类型

每种类型对应 `pages/` 下的一个目录，只能放在对应目录里。不要自造类型，也不要在 `pages/` 根下直接放页面。

| 类型 | 目录 | 一页是什么 | 例子 |
|---|---|---|---|
| `source` | `pages/sources/` | 一个来源的摘要、要点、它改变了哪些判断 | `pages/sources/attention-is-all-you-need.md` |
| `entity` | `pages/entities/` | 一个具体存在：人/组织/产品/作品 | `pages/entities/andrej-karpathy.md` |
| `concept` | `pages/concepts/` | 一个可复用的抽象：术语/理论/方法 | `pages/concepts/scaling-law.md` |
| `topic` | `pages/topics/` | 一个领域的枢纽页，链接并组织下属页面 | `pages/topics/llm-inference.md` |
| `comparison` | `pages/comparisons/` | 多维对比，结论要写进正文而非散落各处 | `pages/comparisons/rag-vs-wiki.md` |
| `answer` | `pages/answers/` | 一次查询沉淀下来的分析结论 | `pages/answers/why-llm-wiki-beats-rag.md` |

`overview.md` 是唯一的全局页，不属于上述分类，不放进子目录，留在 `wiki/` 根——它汇总全库而不是某个主题。

## 3. 命名与链接

**文件名**：英文 kebab-case slug，全小写，用 `-` 分隔，无空格、无中文、无版本号。
- `pages/concepts/context-window.md` ✅
- `概念/上下文窗口.md` ❌
- 理由：wikilink 解析、grep、后续 CLI 检索（qmd 等）与跨平台同步都依赖 ASCII 路径。

**标题**：中文写在 frontmatter 的 `title` 里，页面一级标题与之一致。中文别名写进 `aliases`，方便检索。

**唯一性**：同一 slug 不得出现在两个类型目录。若确有歧义，用 `类型-slug` 形式（如 `pages/entities/apple.md` vs `pages/concepts/apple-silicon.md`）。

**链接**：用 Obsidian wikilink，**最短唯一路径优先**。这是本库区别于 Work 库的特征——路径深了一层，但书写不跟着变长。

- `[[scaling-law]]` —— 全库唯一时默认这么写，不写目录
- `[[pages/concepts/scaling-law]]` —— 仅在需要消歧、或与 `raw/` `meta/` 下的同名文件区分时写全路径
- 正文首次提到某概念时**必须**链到它的页面；页面不存在就顺手建一个（见 §5.3 Lint 的「缺页」项）

短链之所以安全，靠的是上面的唯一性规则：slug 全库唯一，短链就不会解析到别的页面。**所以唯一性规则不能松，松了短链先坏。**

**禁止**：`[文字](相对路径.md)` 这类 Markdown 链接（Obsidian 图谱不认）；外链用普通 Markdown 链接。

## 4. Frontmatter 规范

每个 wiki 页面必须有 YAML frontmatter。字段如下，不用的字段可省略，但不得改名。

```yaml
---
type: concept            # 必填：source|entity|concept|topic|comparison|answer
title: 扩展定律           # 必填：人类可读标题
aliases: [Scaling Law]   # 可选：别名、英文名、旧称
tags: [llm, training]    # 可选：小写、单数、控制在 3 个以内
status: stable           # 必填：draft|stable|stale|disputed
confidence: high         # 可选：high|medium|low，证据强度（见 §6.4）
review: 2027-01-26       # 可选：带时效内容的复核日，逾期 Lint 优先处理（见 §6.3）
sources: [pages/sources/xxx]   # 可选：本页依据的来源页
related: [pages/concepts/yyy]  # 可选：相关页面
created: 2026-10-26      # 必填：YYYY-MM-DD
updated: 2026-10-26      # 必填：任何实质修改都要更新
---
```

`source` 类型额外必填：`raw_path`（指向 `raw/` 下的文件）、`source_type`（article|paper|book|note|transcript）、`author`、`published`。

`status` 的语义：
- `draft` — 刚建，内容不全
- `stable` — 已被足够来源支撑，可以引用
- `stale` — 有新来源推翻了部分内容，等待修订
- `disputed` — 来源之间存在冲突，冲突点必须在正文写清

## 5. 工作流

### 5.1 Ingest（摄入）

来源先落到 `raw/inbox/`，然后：

1. **读**。读全文。图片按需单独看（先读文字，再逐张看 `raw/assets/` 下的图）。
2. **对**。读 `index.md` 与 `overview.md`，弄清这条新信息落在知识地图的哪里。
3. **议**（可选但推荐）。向人汇报 3–5 条关键结论，确认侧重。
4. **筛**。按 §6.1 的准入规则过一遍：够格写的进页面，不够格的留白并写明「来源未涉及 X」，不要把不确定的东西先收进来再想办法圆。
5. **写摘要页**。在 `pages/sources/` 建一页，中文，结构：
   - 一句话结论
   - 核心要点（3–7 条，每条一句，不堆砌）
   - 与已有知识的**关系**：支持了什么、挑战了什么、补充了什么
   - 存疑之处
6. **改周边**。一次 ingest 触及 5–15 页是常态：
   - 相关 `pages/entities/` `pages/concepts/` 页补事实、补链接
   - 相关 `pages/topics/` 枢纽页更新定位
   - 有冲突 → 相关页 `status: disputed`，并在两页各写对方立场
   - 被推翻 → 旧页 `status: stale`，保留旧结论并标注被谁取代（**不要静默删除**）
   - 带时效的事实 → 补时间基准与 `review` 日期（§6.3）
7. **报**。本次摄入发现的相悖、存疑、与旧结论冲突，按 §6.2 的格式向人报告。**这一步不可省略**，页面标记不等于完成了上报。
8. **归档**。把来源从 `raw/inbox/` 移到对应子目录，`pages/sources/` 页的 `raw_path` 同步更新。
9. **记账**。更新 `index.md` 对应分类；重写 `overview.md` 中受影响段落；向 `log.md` 追加一条。

### 5.2 Query（查询）

1. 读 `index.md` 定位候选页（规模到几百页时这一步仍然够用；再大再上搜索工具）。
2. 读候选页及其一跳链接。
3. 作答：**每个论断都要能指回某个页面**，冲突处必须并列呈现，不许替来源下判断；存疑点在回答里要显式标出，不能只藏在页面中（§6.2）。
4. **回填**。值得留存的答案写进 `pages/answers/`，frontmatter `type: answer`，正文末尾列出「依据页面」。同时在 `index.md` 登记、或在相关页 `related` 里加链。
5. 只值得一句话的结论，直接写进对应的 `pages/concepts/` 或 `pages/topics/` 页，不单开页。

判断标准：**这个问题半年后还会被问第二次吗？** 会 → 回填。

### 5.3 Lint（体检）

触发：用户说「体检」，或累计摄入满 10 个来源，或 `overview.md` 的「已知缺口」连续两个月没动。

逐项检查，输出问题清单，逐条修：

- [ ] **矛盾**：两页对同一事实结论相反，且都没标 `disputed`
- [ ] **过时**：新来源已推翻的结论仍标 `stable`；带时效内容没写时间基准（见 §6.3）
- [ ] **复核逾期**：`review` 日期已过但仍标 `stable`
- [ ] **存疑堆积**：正文写着「存疑 / 待考 / 不确定」，或 `confidence: low`，却从未在 ingest / query 时向人提出过
- [ ] **置信虚高**：标 `confidence: high` 但只有单一来源，或证据链中有一环是推断
- [ ] **孤儿**：无任何入链的页面（除 `index.md` / `overview.md` 外）
- [ ] **缺页**：正文反复提到但从未建页的概念/实体
- [ ] **断链**：wikilink 指向不存在的页面
- [ ] **空转**：`draft` 状态超过 30 天未动的页面
- [ ] **索引漂移**：`index.md` 与磁盘实际文件不一致
- [ ] **错位**：页面放错类型目录，或直接堆在 `pages/` 根下（§2 只允许六类目录）
- [ ] **缺口**：本领域明显缺失、可通过一次检索补上的知识

**产出分两处，不能只写一处**：

1. 写入 `meta/lint.md`（覆盖上一版，只保留最新一次）。格式固定为「体检日期 / 规模 / 问题清单（按严重度） / 已修 / 待修 / 建议下一步」。
2. 向 `log.md` 追加一条 `lint` 记录，只写**结论与已修项**，不复述清单。

这样 `meta/lint.md` 给的是「现在还有什么病」，`log.md` 给的是「历次治了什么」，两边互补。

## 6. 严谨性：四条硬约束

「探索型」不等于「什么都收」。本库宁可少一页，不留一条站不住的说法。以下四条优先于 §7 的写作风格：风格可以让步，事实不行。

### 6.1 准入：什么不进库

一条信息要写进页面正文，至少满足一项：

- 有 `pages/sources/` 页可追溯，且能回查原文
- 得到两个以上独立来源交叉印证
- 明确标为「判断」，并给出推理依据

**不达标就不写。** 明确排除以下几类：

| 不收 | 理由 |
|---|---|
| 单一来源的强断言，且该来源利益相关（厂商自述、营销材料、匿名爆料、软文） | 立场污染，无法交叉验证 |
| 无出处的数字、日期、引语、排名、占比 | 不可追溯 = 不可引用 |
| 「业内普遍认为」「大家都知道」 | 无主体、无证据，等于传言 |
| 模型自己的先验记忆、常识推断 | 未经来源确认，容易过时或张冠李戴 |
| 只在对话里出现过、没有任何落盘依据的印象 | 下次会话就找不回来 |

处理方式：**留白 + 标注**。页面写「来源未涉及」或「缺 X 方面证据」，比用流畅措辞把空白填满有价值得多。空白的页面会催你去补来源，注水的页面只会让你以为已经有了。

### 6.2 存疑与相悖：必须当场提出

遇到下列任一情况，**本次 ingest / query 结束前必须向人报告**，不能只在页面里悄悄记一笔就算处理完了。

1. **相悖** —— 两个来源对同一事实给出不同说法
2. **存疑** —— 来源自身有问题：样本不足、口径不明、数据来源不透明、结论与方法不匹配、时间不明
3. **冲突落点** —— 新来源推翻了既有页面的结论

处置动作：

| 情况 | 动作 |
|---|---|
| 两来源冲突 | 两页各标 `status: disputed`，各自写明**对方立场与证据**；`overview.md`「主要分歧」登记 |
| 来源自身存疑 | 摘要页「存疑」段写清存疑点；下游页面引用时降为 `confidence: low` |
| 与既有结论相左 | 旧页标 `stale`，**保留旧结论**并注明被谁取代（§9「不删页」） |
| 无法裁决 | 写明「当前无法裁决，缺 X 方面证据」，同时进 `overview.md`「已知缺口」 |

报告格式，一句话说完：**哪两页或哪两条来源、在哪一点上不一致、各自证据是什么、我倾向哪边及理由**。倾向不明就直说「无法裁决，缺 X」，这也算给出了结论——但必须说清缺什么才能裁决。

反面做法（禁止）：把两个说法揉成一句「有人认为 A，也有人认为 B」然后往下写，页面上不留 `disputed` 标记，也不向人报告。这是最坏的形态：冲突被抹平了，但读者以为已经调和。

### 6.3 时效：主动识别陈旧，不等用户发现

知识会过期，尤其是带版本号、带数字、带法条的东西。出现下列信号，必须标记 `stale` 并给出替代结论：

- **版本迭代** —— 模型版本、API、标准、软件版本、产品线变更
- **日期敏感** —— 带年份的市场份额、基准测试成绩、定价、政策条款、组织架构
- **证据被推翻** —— 原文撤稿、勘误、更正，或后续研究否证
- **口径变化** —— 统计口径、计价单位、汇率、定义改变，导致新旧数据不可比

三条操作约定：

1. **带时效的内容必须写明时间基准**。写「截至 2026-10，X 为 …」，不写裸的绝对数字。没有时间基准的时效性数字，视为未完成，标 `draft`。
2. **已知会过期的页面加 `review: YYYY-MM-DD`**（下次复核日）。到期未复核的页面，Lint 时优先处理。
3. **更新 ≠ 覆盖**。改成「旧结论 + 失效原因 + 新结论」。直接改写会让库失去「曾经怎么想」这条最有价值的信息。

### 6.4 置信分级不是装饰

`confidence` 三级代表证据强度，不代表文章质量：

- `high` —— 多来源交叉印证，或单一权威来源且业界无争议
- `medium` —— 单一可靠来源，或证据链中有一环是推断
- `low` —— 只有弱证据、主要靠推理，或来源立场可疑

**标高了比标低了危险。** 标低只是暂时低估，标高会污染所有下游引用。Lint 时专项检查 `confidence: high` 是否真有多来源支撑（§5.3）。

## 7. 写作原则

1. **结论先行**。每页第一段就是这页的答案，不要铺垫。
2. **可追溯**。任何非常识论断，要么链到 `pages/sources/` 页，要么标 `confidence: low`。
3. **不静默改写**。事实变了，保留旧记录 + 标注取代关系。知识库的价值一半在「曾经怎么想」。
4. **一页一主题**。页面超过 ~400 行或开始出现两套无关论点，就拆分。
5. **链接即价值**。写新页时至少给出 2 个入链、2 个出链；孤立页等于没写。
6. **中文正文，英文标识**。正文中文；目录名、文件名、frontmatter 字段名、tag 用英文。
7. **不注水**。宁可 `draft` 留白，也不写没有信息量的过渡句。

## 8. 索引与日志格式

**index.md** 按类型分区，每行一条：

```
- [[pages/sources/attention-is-all-you-need|Attention Is All You Need]] — Transformer 原始论文，自注意力取代循环结构（2026-10-26）
```

**log.md** 每条形如 `## [YYYY-MM-DD] 动作 | 对象`，动作限定为 `ingest` / `query` / `lint` / `refactor`：

```
## [2026-10-26] ingest | Attention Is All You Need
```

这样 `grep "^## \[" log.md | tail -5` 就能拿到最近 5 条。

## 9. 边界

- **不改** `raw/` 下任何文件内容。可以移动文件做归档，移动后同步 `raw_path`。
- **不造假**。来源里没有的事实、数字、引用，一律不写。缺就写「来源未涉及」。（详见 §6.1 准入）
- **不静默处置冲突**。相悖、存疑、与旧结论冲突，当次必须向人提出（详见 §6.2）。
- **不越权**。`AGENTS.md` 的规则改动要显式说明；不确定就先问人。
- **不删页**。删除只在人明确要求时执行，且先在 `log.md` 记录。
